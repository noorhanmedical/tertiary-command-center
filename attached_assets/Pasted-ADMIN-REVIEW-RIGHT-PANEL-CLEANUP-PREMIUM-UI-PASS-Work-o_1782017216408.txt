================================================================================
SOURCE DATA EDITING
===================

Each Reference section should have an Edit button if editing is supported.

Editable source sections:

* Diagnosis
* Medications
* Symptoms
* Prior Testing

When the user edits source data:

* mark the section as Changed
* mark affected ancillaries as needing regeneration
* block Admin Approve until regeneration is completed
* block packet/PDF generation until regeneration is completed
* show a clear message that regeneration is required

Important rule:
If source data changes, the user must press Generate/Regenerate so the rest of the dependent reasoning updates consistently.

Do not silently approve stale reasoning.

================================================================================
GENERATE / REGENERATE BEHAVIOR
==============================

Use simple wording.

The button should be:

Regenerate

Do not overcomplicate the wording.

If multiple ancillaries were changed, the Updates section should show one Regenerate button that regenerates the appropriate changed ancillaries.

Regenerate should:

* regenerate all applicable changed ancillaries
* preserve assigned evidence
* update clinician understanding
* update patient talking points
* update qualifying factors
* update packet QA status
* clear changed/stale state only after successful regeneration

If regeneration fails:

* keep the ancillary marked as needing regeneration
* show a clear error
* do not allow Admin Approve

================================================================================
PRIOR TESTING RULES
===================

Prior Testing is its own Reference section.

Prior Testing means actual completed prior tests.

Do not show patient history as prior testing.

For example:
If patient history says diabetes, PTSD, headache, craniotomy, hypertension, medications, or symptoms, that is not prior testing.

Prior Testing should only contain actual prior test answers/results/dates when available.

If no real prior testing exists, show:

No prior testing found.

Do not display unrelated patient history under Prior Testing.

Do not treat Symptoms as Prior Testing.
Do not treat Process as Symptoms.
Do not treat patient history as Prior Testing.

================================================================================
REFERENCE SECTION LABELS
========================

Use these clean labels:

Diagnosis
Medications
Symptoms
Prior Testing

Diagnosis comes from DX/source data.
Medications comes from RX/source data.
Symptoms comes from HX/source data when symptoms are present.
Prior Testing comes only from actual previous test data.

Do not call this “Evidence.”
Do not call it “Patient History.”
Do not call it “Process.”

================================================================================
UPDATES SECTION
===============

Updates is very important.

The Updates section should live at the bottom of the right panel.

It should take approximately the bottom one-third of the right panel minimum.

Use title:

Updates

Do not call it:

* Updates Made in Patient
* Decision
* Process
* Patient History
* Evidence

Updates should show what the reviewer changed, grouped by ancillary.

Do not show every action as first, second, third chronological noise.

Group changes by ancillary.

Example:

Updates

BrainWave

* Removed PTSD
* Removed craniotomy

VitalWave

* Added diabetes mellitus
* Added hypertension

Ultrasound

* Removed hypertension
* Added carotid bruit

If I remove PTSD from BrainWave, it should say:

BrainWave

* Removed PTSD

Do not say:

* Removed qualifying factor PTSD

Keep it short and clean.

If I later remove craniotomy from BrainWave, it should group under BrainWave:

BrainWave

* Removed PTSD
* Removed craniotomy

If I add diabetes to VitalWave, group it under VitalWave:

VitalWave

* Added diabetes mellitus

If I remove something from Ultrasound, group it under Ultrasound.

================================================================================
UPDATES + REGENERATE
====================

The Regenerate button belongs in or near the Updates section.

Use simple label:

Regenerate

If there are pending changes, show:

Updates

BrainWave

VitalWave

* Added diabetes mellitus

[Regenerate]

Do not create a huge separate decision box for this.
Do not take up excessive space with a large “Decision” panel.
Do not create a giant box for “Regenerate Changed.”

The Updates section should be compact but important.

After successful regeneration:

* keep a clean history of what changed if available
* clear the “needs regeneration” warning
* allow Admin Approve if no blockers remain
