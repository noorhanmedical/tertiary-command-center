TASK:

Make Admin Review operationally support adding ancillaries, including Ultrasound, to a patient review case.

Current need:
In Admin Review, admin must be able to manually add additional ancillary services such as BrainWave, VitalWave, and Ultrasound. This must be operationally sound, meaning the added ancillary must persist, appear correctly in the review panel, generate/attach correct supporting factors, and flow into patient_execution_cases / Engagement Center / Team Member Portal call lists after approval.

Architecture rules:
- Admin Review is the checkpoint after Plexus IQ and before operational execution.
- The right-side Admin Review panel is the source of truth for selected ancillaries and supporting factors.
- patient_execution_cases is the source of truth for assigned operational work after approval.
- Engagement Center assigns work.
- Team Member Portal is where ACS/PCS works call lists.
- Do not use /api/scheduler-assignments for Engagement Center-assigned call work.
- Do not resurrect old Outreach Center.
- Do not create duplicate ancillary cases.
- Do not wipe existing ancillaries when adding or regenerating one ancillary.
- Do not change schema unless absolutely required.

PART 2 — Add service picker in Admin Review

In the Admin Review right-side panel, add a clean premium service/ancillary picker.

Admin should be able to add:
- BrainWave
- VitalWave
- Ultrasound

If other ancillary services are already configured, preserve them.

UI requirements:
- Do not use a cluttered pill-heavy design.
- Use clean service cards or rows.
- Each selected ancillary should show:
  service name
  status
  supporting diagnoses
  supporting factors
  qualification reason
  PDF status if available
  execution case status if available

For Ultrasound:
- Add Ultrasound as a selectable ancillary.
- If ultrasound subtype support already exists, allow optional subtype.
- If not, use generic Ultrasound with optional notes/reason field.
- Do not invent unsupported clinical subtype logic.

PART 3 — Prevent duplicates

Prevent duplicate service entries for the same patient/review unless intentionally distinct by subtype.

Rules:
- Adding Ultrasound twice should not create duplicate Ultrasound rows.
- Instead, focus the existing Ultrasound row and allow adding/editing supporting diagnoses/factors.
- Same for BrainWave and VitalWave.
- The same supporting button/factor may apply to multiple targets if clinically relevant.
- Dedupe per target/service, not globally across all services.

PART 4 — Preserve existing ancillaries

Adding or editing one ancillary must not delete or overwrite others.

Required behavior:
- Add Ultrasound while BrainWave exists → BrainWave remains unchanged.
- Add BrainWave while Ultrasound exists → Ultrasound remains unchanged.
- Regenerate Ultrasound only → only Ultrasound factors/reason update.
- Regenerate BrainWave only → only BrainWave factors/reason update.
- Regenerate all → all selected ancillaries update.
- Save review → all selected ancillaries persist.

This is critical.

PART 5 — Supporting diagnoses and factors

Each ancillary must support:
- supporting diagnoses
- supporting factors
- qualification reason
- admin notes if available
- source: generated by Plexus IQ vs added by admin

If admin adds Ultrasound manually:
- mark source as admin_added or equivalent if existing field supports it
- require or strongly prompt for supporting reason/factors
- do not fake diagnosis support if none is selected
- allow admin to select/add supporting factors from existing available factors/buttons

Derived qualifying_factors should come from the selected services in the right panel, not from stale generated data.

PART 6 — Approval behavior

When admin approves selected ancillaries:
- create or update operational cases in patient_execution_cases for each approved service/ancillary
- do not create duplicates
- preserve existing execution cases
- update existing cases if the service already exists
- set the correct target ancillary/workflow category
- include callReason based on service:
  BrainWave outreach
  VitalWave outreach
  Ultrasound scheduling
- include supporting diagnoses/factors if existing schema supports it
- set status appropriate for Engagement Center assignment, such as ready_to_assign / pending_engagement / approved, based on current app conventions

Do not invent new statuses if existing status constants exist.
