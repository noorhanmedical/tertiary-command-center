TASK:

Redesign Patient Directory into a true premium EMR-style patient chart with full patient-data categories and cooldown/ad-automation visibility.

Current problem:
Patient Directory is too thin and does not feel like a real EMR. It needs to support the full patient record because future API integrations will bring in complete patient data. It also needs to make cooldown a major concept on the patient overview, because cooldown controls outreach, re-engagement, and automated ad/message eligibility.

Architecture rules:
- Patient Directory is the canonical patient identity/profile/chart area.
- Patient Directory must display real patient data from existing patient directory/API sources.
- Do not invent fake patient data.
- Use graceful empty states for unavailable data.
- Playground remains the operational workspace.
- Team Member Portal remains the call-list workspace.
- Mission Control remains the executive/admin oversight dashboard.
- Do not use old Outreach Center.
- Do not create a new source of truth.
- Do not change schema unless absolutely required.
- Build the UI to be API-integration-ready.

Visual direction:
- Premium EMR style
- Bright and bold
- iOS-like
- Clean white cards
- Large section headers
- Organized tables
- Timeline blocks
- Minimal pills/badges
- Stop relying on pill-heavy UI
- No cramped side drawer
- No cheap CRM panel
- No clutter

When a patient is selected, Patient Directory should show a full EMR-style patient chart/profile.

Use a clear patient header:
- patient name

- patient ID
- phone
- email if available
- clinic/facility
- provider

PART 4 — Ad Automation section

Add an “Ad Automation” section/card.

This matters because the company will use cooldown to determine automated patient education/ad/message eligibility.

Show:
- campaign eligibility
- current campaign if available
- suggested campaign if available
- last message/ad sent if available
- next scheduled send if available
- consent/channel status if available
- suppression reason
- cooldown impact
- re-engagement eligibility
- passive education eligibility

Example display logic:
- If cooldown blocks calls but allows passive ads, show:
  “Phone outreach paused. Passive education campaign eligible.”
- If do-not-contact blocks everything, show:
  “All outreach suppressed.”
- If clear, show:
  “Eligible for outreach and automation.”

Do not fake live campaigns if none exist. Show “No active automation campaign connected yet.”
