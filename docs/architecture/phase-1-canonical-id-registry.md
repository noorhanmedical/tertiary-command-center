# Phase 1 — canonical ID registry

**Status:** Docs-only (Batch C2 of Phase 1 run).
**Companion:** `scripts/qa-phase-1-canonical-id-registry.mjs`.

Pins the canonical IDs used across Phase 1 — who generates each ID, who writes it, who reads it, and the no-split-brain rule.

## patientId / Patient Directory ID

- **Source owner:** Patient Directory (canonical patient identity façade — Bundle 5 / Bundle 20 designs).
- **Generated by:** Patient Directory canonical-write surface (when implemented). Today the de-facto identity lives on `patient_screenings.id`.
- **Consumed by:** All Phase 1 modules.
- **Write owner:** Patient Directory façade (future). Today multiple writers per the #163 Batch 4 audit.
- **Read consumers:** Engagement Center, Team Portal, Plexus IQ, Admin Review, Ancillary, Billing.
- **No-split-brain rule:** ONE canonical patient identity per real patient; multi-row deduplication is the directory's job.

## patientScreeningId

- **Source owner:** Batch Flow ingestion (`patient_screenings` table).
- **Generated by:** Batch ingestion routes (`routes/batches.ts`).
- **Consumed by:** EVERY Phase 1 module — it's the universal join key.
- **Write owner:** `storage.createPatientScreening` / batch ingest.
- **Read consumers:** Plexus IQ reasoning, Admin Review, Engagement Center, Team Portal, Ancillary, Billing.
- **No-split-brain rule:** No module fabricates patientScreeningId; all reads go through `patient_screenings` or the future Patient Directory.

## executionCaseId

- **Source owner:** Execution Case service / `patient_execution_cases` table.
- **Generated by:** Engagement Center commit (Admin Review approval triggers execution-case creation).
- **Consumed by:** Engagement Center board, Team Portal call-list, Operational Queue projection, recordCallResult deps.
- **Write owner:** Execution Case service (future canonical writer); today six files write the table per #160 Batch 1 audit.
- **Read consumers:** Engagement Center reads, call-result writers (via dep injection), Operational Queue, Plexus IQ aggregation.
- **No-split-brain rule:** Engagement-case lifecycle state belongs to the execution-case service; no other module mutates it.

## batchId

- **Source owner:** Batch Flow (`screening_batches` table).
- **Generated by:** Batch ingestion routes.
- **Consumed by:** Plexus IQ batch-flow analysis, Admin Review per-batch review surface, Engagement Center board (batch filter).
- **Write owner:** `routes/batches.ts` + bulk-ingest service.
- **Read consumers:** Plexus IQ, Admin Review, Engagement Center, Team Portal (when scoping work).
- **No-split-brain rule:** Batch state lives on `screening_batches`; downstream surfaces JOIN, they do not duplicate.

## ancillaryId / ancillaryType

- **Source owner:** Ancillary documents module (Segment F future).
- **Generated by:** Ancillary order creation when implemented; today implicit on the screening row's ancillary fields.
- **Consumed by:** Documents tracking, physician signing queue, billing readiness blocker chips, Team Portal patient panel.
- **Write owner:** Ancillary service (future); today varies per ancillary type.
- **Read consumers:** Team Portal blocker chips, billing readiness, Plexus IQ aggregation.
- **No-split-brain rule:** Ancillary state owned by the ancillary module; not by Team Portal or Plexus IQ.

## assignmentId

- **Source owner:** Scheduler assignment service / `scheduler_assignments` table.
- **Generated by:** Daily build + manual assignment routes.
- **Consumed by:** Team Portal day-of call list, Operational Queue, outreach call-result completion logic.
- **Write owner:** Scheduler assignment service + auto-assign + bridge module + outreach route's `markSchedulerAssignmentCompleted`.
- **Read consumers:** Team Portal, Operational Queue, recordCallResult deps.
- **No-split-brain rule:** Assignment lifecycle owned by the assignment service; reads everywhere are JOIN-based.

## taskId

- **Source owner:** Team Tasks (`plexus_tasks` table).
- **Generated by:** `storage.createTask` / Team Tasks routes / engagement-route delegation deps.
- **Consumed by:** Team Tasks UI, Team Portal patient panel chips, Engagement Center board (open-tasks count).
- **Write owner:** `storage.createTask` (canonical writer per #161 Batch 2 registry).
- **Read consumers:** Team Tasks, Team Portal, Engagement Center.
- **No-split-brain rule:** Task creation goes through `storage.createTask` only. No parallel writers.

## triageCaseId

- **Source owner:** Scheduling triage (`scheduling_triage_cases` table).
- **Generated by:** `upsertOpenSchedulingTriageCase` (canonical writer per #161 Batch 2 registry).
- **Consumed by:** Scheduling triage UI, Team Portal blocker chips, Engagement Center board.
- **Write owner:** `upsertOpenSchedulingTriageCase`.
- **Read consumers:** Scheduling triage routes, Team Portal, Engagement Center.
- **No-split-brain rule:** Triage rows go through the canonical upsert; no parallel writers.

## journeyEventId

- **Source owner:** Journey Events (`patient_journey_events` table).
- **Generated by:** `appendJourneyEvent` (Bundle 12c canonical writer per #161 Batch 2 registry).
- **Consumed by:** Engagement Center timeline, Plexus IQ reasoning, Admin Review evidence, billing readiness audit, Team Portal patient panel (when surfaced).
- **Write owner:** `appendJourneyEvent` ONLY (per #161 registry; 2 baseline parallel writers tracked by #162 Batch 3 scanner pending consolidation).
- **Read consumers:** Engagement Center, Plexus IQ, Admin Review, Team Portal, Operational Queue, billing readiness.
- **No-split-brain rule:** `appendJourneyEvent` is THE canonical writer. The 2 baseline parallel writers consolidate in a separate Admin-Review-reasoning-cleanup PR series.

## documentId

- **Source owner:** Ancillary documents module (Segment F future).
- **Generated by:** Document creation / upload / generation routes.
- **Consumed by:** Documents library, physician signing queue, billing readiness, Team Portal patient panel.
- **Write owner:** Documents service (future).
- **Read consumers:** Documents library, signing queue, billing readiness, Team Portal.
- **No-split-brain rule:** Document state owned by the documents service; not by Plexus IQ or Admin Review.

## signatureId

- **Source owner:** Physician signing queue (Segment F future).
- **Generated by:** Signature action UI / routes.
- **Consumed by:** Documents library, billing readiness, audit trail.
- **Write owner:** Signing service (future).
- **Read consumers:** Documents library, billing readiness, audit trail.
- **No-split-brain rule:** Signature events go through the signing service; Plexus IQ + Admin Review don't sign.

## billingReadinessId

- **Source owner:** Billing Readiness module (Segment G future).
- **Generated by:** Readiness evaluation service (when implemented).
- **Consumed by:** Billing Readiness UI, Invoicing draft step, Team Portal blocker chips.
- **Write owner:** Billing Readiness service (future).
- **Read consumers:** Billing Readiness UI, Invoicing, Team Portal.
- **No-split-brain rule:** Readiness owned by the billing-readiness module. Plexus IQ READS it; doesn't compute it.

## invoiceId

- **Source owner:** Invoicing module (Segment G future).
- **Generated by:** Invoice draft action.
- **Consumed by:** Invoicing UI, audit trail.
- **Write owner:** Invoicing service (future).
- **Read consumers:** Invoicing UI, audit trail.
- **No-split-brain rule:** Invoices live in the invoicing module; NOT in Plexus IQ. Phase 1 invoicing is NOT claims submission.

## ringCentralCallId / sessionId

- **Source owner:** RingCentral telephony adapter (Segment E future).
- **Generated by:** RingCentral webhook / SDK on call initiation.
- **Consumed by:** Call-result metadata bag (`callMetadata.ringCentralCallId` per Batch B4 args extension), Team Portal call history.
- **Write owner:** Inbound webhook / SDK adapter (telephony layer only).
- **Read consumers:** Team Portal call history panel, call-result audit metadata.
- **No-split-brain rule:** RingCentral is telephony adapter ONLY; metadata attaches to the canonical call result; RingCentral does NOT own workflow state.

## Phase 1 rules

- One canonical writer per canonical ID.
- All cross-module references use the canonical ID; no parallel ID schemes.
- Plexus IQ does NOT mint operational IDs.
- Admin Review does NOT mint operational IDs.
- Team Portal CONSUMES IDs; does not generate them.
