## Summary
- **VERIFIED:** 26 / 26 · **PARTIAL:** 0 · **MISSING:** 0 · **CONFLICTING:** 0

- **Audit-pass fix (1 MAJOR):** the payment allocation *write* path previously gated a
  target only on payable-status, so a still-payable but lineage-stale target (membership
  deactivated / global patient merged / evidence superseded / invoice↔claim drift) could
  be driven to `paid` while the read model reported it `conflicting`. Fixed by
  `paymentCommands.validateTargetLineage`, which reruns the SAME shared lineage validators
  used by the read model inside `allocateCanonicalPayment` before any insert (domain 11).
  Negation (refund/reversal) is deliberately not gated — it only unwinds and never
  transitions a target *into* `paid`, and blocking it would strand money as paid.
